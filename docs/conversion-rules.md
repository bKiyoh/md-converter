# 変換ルール

## エディター入力時のリストインデント

エディターのリスト編集支援では、入力Markdownのネストを1階層につき半角スペース2個で挿入・削除する。この規則は入力支援の操作単位であり、各Converterの出力規則は以下の形式別仕様を優先する。たとえばBacklog Markdownの出力では、既存仕様どおりネストを4スペースで再構築する。

| Markdown要素     | 入力例        | Slack         | Backlog Markdown | Backlog記法         | プレーンテキスト |
| ---------------- | ------------- | ------------- | ---------------- | ------------------- | ---------------- |
| 見出し1          | `# 見出し`    | `*見出し*`    | `# 見出し`       | `* 見出し`          | `【見出し】`     |
| 見出し2          | `## 見出し`   | `*見出し*`    | `## 見出し`      | `** 見出し`         | `■ 見出し`       |
| 見出し3          | `### 見出し`  | `*見出し*`    | `### 見出し`     | `*** 見出し`        | `▼ 見出し`       |
| 見出し4以降      | `#### 見出し` | `*見出し*`    | `#### 見出し`    | `*** 見出し`（警告） | `● 見出し`（警告） |
| 太字（文中）     | `**重要**`    | `*重要*`      | `**重要**`       | `''重要''`          | `「重要」`       |
| 斜体             | `*補足*`      | `_補足_`      | `*補足*`         | `'''補足'''`        | `補足`           |
| 打ち消し線       | `~~廃止~~`    | `~廃止~`      | `~~廃止~~`       | `%%廃止%%`          | `廃止`           |
| リンク           | `[名称](URL)` | `[名称](URL)` | `[名称](URL)`    | `[[名称:URL]]`      | `名称（URL）`    |
| 未完了タスク     | `- [ ] 対応`  | `☐ 対応`      | `- [ ] 対応`     | `- [ ] 対応`        | `□ 対応`         |
| 完了タスク       | `- [x] 対応`  | `☑ 対応`      | `- [x] 対応`     | `- [x] 対応`        | `■ 対応`         |
| 引用             | `> 引用`      | `> 引用`      | `> 引用`         | `> 引用`            | `> 引用`         |
| インラインコード | `` `code` ``  | `` `code` ``  | `` `code` ``     | `code`（警告）      | `` `code` ``     |
| 水平線           | `---`         | `──────────`  | `---`            | `──────────`（警告） | `──────────`     |

## Slackのテーブル

Markdownテーブルはコードブロック形式へ変換する。

入力：

```md
| 項目 | 内容         |
| ---- | ------------ |
| 事象 | 保存できない |
| 原因 | 空文字       |
```

## Slack変換の対象と補足

Slack変換は、Slack APIの `mrkdwn` ではなく、Slackのメッセージ入力欄で「マークアップでメッセージを書式設定する」を有効にした場合の記法を対象とする。したがって、リンクにはAPI向けの `<URL|名称>` ではなく、入力欄向けの `[名称](URL)` を使用する。

- 見出しは同等の記法がないため太字へ変換し、見出しレベルが失われる警告を返す。
- 箇条書きは `- `、番号付きリストは実際の番号と `. ` を使用する。ネストは2スペースのインデントで表す。
- チェックリストは未完了を `☐`、完了を `☑` で表し、操作可能なチェックボックスではなくなる警告を返す。
- コードブロックは3つのバッククォートで囲む。言語名またはメタ情報がある場合、それらはSlackのコードブロックでは保持できないため警告を返す。
- テーブルはパイプ区切りの内容をコードブロックへ変換し、表固有の配置やセル内装飾が失われる警告を返す。
- 水平線は `──────────` へ変換し、水平線としての構造が失われる警告を返す。
- ソフト改行と明示的な改行はいずれも改行文字として保持する。段落などブロック間は空行で区切る。

参照したSlack公式仕様：

- [Format your messages in Slack with markup](https://slack.com/help/articles/360039953113-Format-your-messages-in-Slack-with-markup)
- [Format your messages in Slack](https://slack.com/help/articles/202288908-Format-your-messages-in-Slack)

## Backlog Markdown変換の対象と補足

Backlog Markdown変換は、2025年10月23日以降のGitHub Flavored Markdown準拠のMarkdown記法を対象とする。入力をそのまま返さず、構文解析後の中間表現からBacklogで解釈できるMarkdownを再構築する。

- 見出しはレベル1〜6を `#` の個数で保持する。
- 太字、斜体、打ち消し線、リンク、インラインコード、引用、水平線はGFMと同じ記法を使用する。
- 箇条書きは `- `、番号付きリストは実際の番号と `. ` を使用する。ネストおよびリスト項目内の継続行は4スペースでインデントする。
- チェックリストは未完了を `- [ ]`、完了を `- [x]` で表す。ただし、操作可能なチェックリストとして利用できるのは課題詳細のみであるため、変換時に利用箇所の制約を警告する。
- コードブロックは3つ以上のバッククォートで囲み、言語名とメタ情報を保持する。本文中のバッククォートと衝突する場合は、より長いフェンスを使用する。
- テーブルはパイプ区切りで出力し、左寄せ、中央寄せ、右寄せの列配置とセル内装飾を保持する。
- ソフト改行は改行文字として保持する。明示的な改行は行末2スペースと改行文字で表し、段落などブロック間は空行で区切る。
- Markdownとして再解釈され得る通常テキストの記号は、意味が変わらないよう必要な範囲でエスケープする。

参照したBacklog公式仕様（2026-07-11確認）：

- [テキスト整形のルール (Markdown 記法)](https://support-ja.backlog.com/hc/ja/articles/360036145833-%E3%83%86%E3%82%AD%E3%82%B9%E3%83%88%E6%95%B4%E5%BD%A2%E3%81%AE%E3%83%AB%E3%83%BC%E3%83%AB-Markdown-%E8%A8%98%E6%B3%95)
- [GitHub Flavored Markdown とMarkdownで互換性の違いはありますか？](https://support-ja.backlog.com/hc/ja/articles/48111344659353-GitHub-Flavored-Markdown-%E3%81%A8Markdown%E3%81%A7%E4%BA%92%E6%8F%9B%E6%80%A7%E3%81%AE%E9%81%95%E3%81%84%E3%81%AF%E3%81%82%E3%82%8A%E3%81%BE%E3%81%99%E3%81%8B)

## Backlog記法変換の対象と補足

Backlog記法変換は、Backlog公式ヘルプの「テキスト整形のルール (Backlog記法)」で確認できる記法だけを使用する。

- 見出しは、公式例で確認できるレベル1〜3を行頭の `*` の個数で表す。レベル4〜6はレベル3へ変換し、見出しレベルが失われる警告を返す。
- 太字は `''`、斜体は `'''`、打ち消し線は `%%` で囲む。公式仕様で挙動を確認できない装飾の入れ子は、内側の装飾をプレーンテキスト化して警告を返す。
- 箇条書きは階層の深さに応じた `-` の個数、番号付きリストは `+` の個数で表す。番号付きリストは開始番号を指定できないため、1以外で始まる場合は警告を返す。
- チェックリストは `- [ ]` と `- [x]` で表す。操作可能なチェックリストとして利用できるのは課題詳細のみであるため、警告を返す。
- 引用は各行の先頭に `>` を付ける。
- コードブロックは `{code}` と `{/code}` で囲む。言語は公式例で確認できる `java` と `cs` だけを保持し、それ以外の言語名とメタ情報は省略して警告を返す。
- Markdownのインラインコードに対応するBacklog記法は公式仕様で確認できないため、コード本文をプレーンテキストとして保持し、装飾が失われる警告を返す。
- リンクは `[[名称:URL]]` で表す。Markdownのリンクタイトルは保持できないため、省略して警告を返す。
- テーブルはパイプ区切りで出力し、ヘッダー行の末尾に `h` を付ける。列配置は保持できないため、配置指定がある場合は警告を返す。
- ソフト改行と明示的な改行は、公式に確認できる `&br;` で保持する。段落などのブロック間は空行で区切る。
- 水平線に対応するBacklog記法は公式仕様で確認できないため、罫線文字 `──────────` へ変換し、水平線としての構造が失われる警告を返す。
- Backlog記法として解釈され得る通常テキストの特殊文字は、公式どおり2つのバックスラッシュによるエスケープを使用して意味が変わらないようにする。

参照したBacklog公式仕様（2026-07-11確認）：

- [テキスト整形のルール (Backlog記法)](https://support-ja.backlog.com/hc/ja/articles/360035641594-%E3%83%86%E3%82%AD%E3%82%B9%E3%83%88%E6%95%B4%E5%BD%A2%E3%81%AE%E3%83%AB%E3%83%BC%E3%83%AB-Backlog%E8%A8%98%E6%B3%95)

## プレーンテキスト変換の対象と補足

プレーンテキスト変換は、Markdownの装飾記号を取り除きつつ、見出し、リスト、引用、コード、テーブルなどの文章構造と本文を読み取れる代替表現で保持する。

- 見出しレベル1は `【見出し文字列】`、レベル2は `■ 見出し文字列`、レベル3は `▼ 見出し文字列`、レベル4〜6は `● 見出し文字列` とする。レベル4〜6は同じ小見出し表現へ統合されるため、その見出しごとにレベル情報が失われる警告を返す。見出しの前後をほかのブロックと1行の空行で区切り、出力の先頭・末尾には余分な空行を付けない。
- 文中の太字は `「本文」` とする。段落全体が1つの太字だけで構成される場合は `【本文】` とするが、見出しとしては扱わない。斜体と打ち消し線は装飾記号を取り除いて本文を保持する。これらの通常変換では警告を返さない。
- インラインコードはバッククォートで囲んだまま保持し、警告を返さない。
- リンクは `名称（URL）` として表示名とURLを保持する。リンクタイトルがある場合は省略し、リンクごとに警告を返す。
- 箇条書きは `- `、番号付きリストは開始番号を含む実際の番号と `. ` を使用する。ネストは1階層につき2スペースで表す。
- チェックリストは未完了を `□ `、完了を `■ ` で表す。操作可能なチェックボックスではなくなるため、チェック項目ごとに警告を返す。
- 引用は内部の改行と空行を保持し、各行の先頭に `>` を付ける。
- コードブロックはフェンスを取り除き、本文の各行の先頭に4スペースを付ける。本文中の改行と空白は保持する。言語名またはメタ情報がある場合だけ、それらを省略してコードブロックごとに1件の警告を返す。
- 2列のテーブルはヘッダー行を出力せず、各データ行を `1列目：2列目` として出力する。3列以上のテーブルはヘッダー行を含め、セル間をタブ、行間を改行として出力する。どちらもMarkdownのヘッダー区切り行は出力しない。セルの本文は装飾記号を取り除いて保持する。明示的な列配置またはセル内装飾がある場合は省略し、テーブルごとに1件の警告を返す。
- 水平線は `──────────` へ変換し、警告は返さない。
- ソフト改行と明示的な改行はいずれも改行文字として保持する。リスト項目、引用、コードブロック内の改行も保持する。段落などのブロック間は1行の空行で区切り、連続した余分な空行は作らない。
- 不完全なMarkdownがCommonMark/GFMで通常テキストとして解析された場合は、その文字を保持し、推測による警告は返さない。
- 警告は情報が実際に欠落する場合だけ返し、代替記号への通常変換だけでは返さない。同一種類の情報損失は、上記に定めたレベル4〜6の見出し、リンク、チェック項目、コードブロック、テーブルの各出現単位で返す。

## MVP対象外の生HTML

生HTMLはMVPの変換対象には含めず、HTMLとして解釈または実行しない。ただし、生HTMLが含まれることだけを理由に文書全体の変換を停止しない。

- ブロックHTMLとインラインHTMLは、元の文字列と位置情報を中間表現へ保持する。
- 各Converterは、出力先の記法として再解釈されないよう既存のテキスト用エスケープを適用し、文字列として出力する。
- 生HTMLノードごとに `unsupported-node` 警告を返し、HTMLとしては変換していないことを通知する。
- 生HTMLのタグ除去や内容の再解釈は行わない。HTMLパーサーを追加せず、入力文字列の欠落を避けるためである。
- Markdownプレビューでは従来どおり生HTMLを破棄し、DOMへ出力しない。
- 生HTML以外の変換可能な要素は通常どおり変換を継続する。
- 生HTMLを理由にUI境界の汎用例外処理へ到達させない。生HTML以外のMVP対象外要素は、要素ごとにフォールバック仕様を決めるまで既存動作を維持する。
