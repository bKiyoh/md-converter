# 全角Markdown補正仕様

> 文書区分：現行仕様。文書の役割と読む順番は
> [`docs/README.md`](../README.md) を参照してください。

## 1. 目的

日本語IMEなどでMarkdown記号を全角入力した場合に、入力またはIME確定の直後に対応する半角記号へ補正し、既存のGFMパーサーでMarkdownとして解釈できるようにする。

本文全体の文字種変換や表記ゆれ吸収は行わず、ユーザーが意図して使用した全角英数字、全角空白、記号、半角カナなどを変更しない。

画面上の名称は「全角Markdown補正」、説明は「全角で入力したMarkdown記号を、入力直後に半角へ補正します。」とする。

## 2. 設定

- 初期状態はOFFとする。
- 既存の設定ポップオーバーへON/OFFスイッチを追加する。
- 設定はアプリ全体で共通とし、通常モードとフォーカスモードで同じ値を使用する。
- `localStorage` の既存キー `md-converter:settings:v1` にbooleanの `normalizeFullWidthMarkdown` を追加し、変更時に即時保存する。
- 既存の保存値に `normalizeFullWidthMarkdown` がない場合、不正な型の場合、またはLocalStorageを利用できない場合はOFFへフォールバックする。

## 3. 適用対象

- 選択中タブのMarkdown本文を編集する既存のtextareaだけを対象とする。
- `beforeinput`による直接入力とIME確定後の`compositionend`では、今回入力された全角Markdown記号を1文字から半角へ補正する。
- 修飾キーなしのEnterでは、現在行に残っている行頭構文、区切り空白、テーブルなどを補正してからリスト継続を判定する。
- IME変換中は補正しない。
- 補正結果は既存の本文更新と自動保存経路へ渡し、保存するMarkdown本文も半角化後の値とする。
- 補正によってプレビュー、変換結果、検索結果、文字数を通常の本文編集と同じ経路で更新する。
- 1回の入力で全角Markdown補正、入力置換、改行、リスト継続が必要な場合は、可能な限りtextareaへ1回の編集として反映する。

次は適用対象外とする。

- 貼り付け
- ドラッグ＆ドロップ
- 保存内容の復元
- タブ切り替え
- 検索・一括置換
- Undo／Redo
- タブ名、検索・置換欄、設定などMarkdown本文以外の入力欄

## 4. 補正対象

設定がONの場合、インライン構文に使用する全角記号は1文字入力した時点で半角へ補正する。行頭構文、番号、区切り空白、チェック状態、テーブル区切りはMarkdownとして使用される位置だけを補正する。

| Markdown要素 | 全角入力例 | 補正後 |
| --- | --- | --- |
| 見出し | `＃　見出し` | `# 見出し` |
| 箇条書き | `－　項目`、`ー　項目`、`＋　項目`、`＊　項目` | `- 項目`、`- 項目`、`+ 項目`、`* 項目` |
| 番号付きリスト | `１．　項目` | `1. 項目` |
| チェックリスト | `－　［ｘ］　項目` | `- [x] 項目` |
| 引用 | `＞　引用` | `> 引用` |
| 太字・斜体 | `＊＊重要＊＊`、`＊補足＊` | `**重要**`、`*補足*` |
| 打ち消し線 | `～～廃止～～` | `~~廃止~~` |
| インラインコード | `｀code｀` | `` `code` `` |
| コードフェンス | `｀｀｀`、`～～～` | `` ``` ``、`~~~` |
| リンク | `［名称］（https://example.com）` | `[名称](https://example.com)` |
| テーブル | `｜ 項目 ｜ 内容 ｜` | `| 項目 | 内容 |` |
| 水平線 | `－－－` | `---` |

補足：

- 行頭構文の直後にある全角空白は、Markdownの区切りとして必要な範囲だけ半角空白へ補正する。
- 日本語IMEでハイフンの代わりに入力される長音記号 `ー` は、行頭の箇条書き候補として入力された時点で半角ハイフンへ補正する。通常文章中の長音記号は変更しない。
- 番号付きリストの全角数字は行頭のリスト番号として成立する場合だけ半角化する。
- テーブルの区切り行では、全角のハイフンとコロンを半角化する。
- リンク先文字列や通常本文の全角英数字は変更しない。
- 画像は対応範囲外のため、全角の感嘆符を画像記法へ補正しない。

## 5. 誤補正の防止

- UnicodeのNFKC正規化をMarkdown本文全体へ適用しない。
- `＃`、`－`、`ー`、`＋`、`＞`、全角数字など、ブロック構文用の文字はMarkdownの行頭候補位置だけで補正する。
- `＊`、`＿`、`～`、`｀`、`［`、`］`、`（`、`）`、`｜`は開始・終了記号を入力しやすくするため、1文字の入力時点で補正する。
- 既存のGFMパーサーの位置情報を使用し、インラインコードとコードブロックの本文では補正しない。
- 全角コードフェンスはコード構造を開始または終了する記号として補正するが、フェンス内の本文は変更しない。
- Markdownから各出力形式への変換は従来どおりASTを経由し、この入力補正UtilityでConverterの処理を代替しない。

## 6. 入力置換・リスト継続との順序

同じ入力契機で複数の入力支援が必要な場合は、次の順序で計算する。

1. 全角Markdown補正
2. ユーザー登録ルールによる入力置換
3. Enterによる改行とMarkdownリスト継続

全角Markdown補正によってMarkdown構文が成立した場合は、その入力範囲の補正を優先し、同じ全角文字列を入力文字とするユーザー登録ルールは連続適用しない。

## 7. Undo／Redo

補正範囲を既存の`applyEditorTextEdit`へ渡し、可能な限りブラウザのネイティブ編集履歴へ1回の編集として追加する。ネイティブ編集が利用できない場合は既存の`setRangeText`フォールバックを使用し、本文、カーソル、選択範囲を維持する。

ブラウザ標準Undo履歴には実装差があるため、自動テストに加えて対象ブラウザで次を確認する。

- IME確定後の補正をUndo／Redoできる。
- SpaceとEnterを契機にした補正をUndo／Redoできる。
- Undo／Redoで復元された本文へ補正を再適用しない。
- 入力置換とリスト継続を伴う補正が不自然に分割されない。

## 8. テスト

- 設定の初期OFF、ON/OFF、保存・復元、旧保存値、不正値、Storage例外
- 見出し、箇条書き、番号付きリスト、チェックリスト、引用
- 太字、斜体、打ち消し線、インラインコード、コードフェンス
- リンク、テーブル、水平線
- 半角Markdownを変更しないこと
- 通常文中の全角記号、全角英数字、全角空白を変更しないこと
- インラインコードとコードブロック本文の除外
- IME確定、直接入力、Space、全角Space、Enter、カーソル位置
- 貼り付け、検索置換、復元、タブ切り替え、Undo／Redoの除外
- 入力置換、リスト継続、通常モード、フォーカスモードとの回帰
