# フォーカスモード仕様

> 文書区分：現行仕様。文書の役割と読む順番は
> [`docs/README.md`](../README.md) を参照してください。

## 1. 目的

Markdownの入力作業に集中できるよう、通常画面の機能を一時的に非表示にし、現在選択しているタブの編集領域またはMarkdownプレビューを表示する。

専用画面への遷移、モーダル表示、ブラウザFull Screen APIは使用せず、通常画面のレイアウトをフォーカスモード用に切り替える。

## 2. フォーカスモードへの切り替え

- 通常ヘッダーの左端にフォーカスモード切り替えアイコン、その右隣にタイトルアイコンを表示する。
- 押下するとフォーカスモードへ切り替える。
- 通常モードでEscapeキーを押した場合もフォーカスモードへ切り替える。ただし、タブ名編集、設定、警告、情報モーダルなどがEscapeキーを処理した場合は、その操作だけを行う。
- 切り替え前のカーソル位置、選択範囲、textareaのスクロール位置を維持し、切り替え直後にエディターへ自動フォーカスする。
- 狭い画面で変換結果を表示していた場合も、入力ペインへ切り替えてエディターを表示する。

## 3. PC表示のレイアウト

768px以上では画面を3領域に分ける。通常画面の左右ペイン比率は使用せず、保存値も変更しない。

| 領域 | 幅 | 内容 |
| --- | ---: | --- |
| 左 | 中央領域を除いた幅の1/2 | 終了・解説操作 |
| 中央 | 下記の可変幅 | タブ名とエディター／プレビュー |
| 右 | 中央領域を除いた幅の1/2 | 空白 |

- 768px以上960px未満では、ウィンドウを左右へ分割した場合も入力幅を確保するため、中央領域を画面幅と同じ幅にする。
- 960px以上1760px以下では、中央領域を960pxとする。
- 1760pxを超えると中央領域を画面幅に応じて滑らかに増やす。
- 長文の視線移動が過度にならないよう、中央領域は1680pxを上限とする。
- 左右の残り幅は均等に分け、中央領域を画面中央に維持する。

解説欄の開閉によって中央領域の幅や位置を変更しない。
この幅は外側の配置領域を表す。内側の編集列と本文幅は第5章の上限に従う。

## 4. 左領域

1440px以上では、左領域を画面上に固定し、中央領域のスクロールに追従させない。上から次の順に配置する。

1. フォーカスモード終了用の「×」アイコン、解説欄を開閉する「？」アイコンを横並びで表示する
2. 解説欄

768px以上1440px未満では、中央領域の入力幅を優先し、操作アイコンを画面左上へ重ねて固定する。解説欄は画面左端から重ねるドロワーとして表示し、中央領域の幅を変更しない。タブ名には操作アイコンと重ならないための余白を確保する。

### ×アイコン

- 左領域の左上に配置する。
- 押下すると通常モードへ戻る。
- フォーカスモード中は常に表示する。

### ？アイコン

- ×アイコンの右隣に配置する。
- 押下するたびに解説欄を開閉する。
- `aria-expanded` と操作内容を示すラベルを設定する。

### 解説欄

- フォーカスモード開始時は閉じる。
- 入力支援は「フォーカスモード」「装飾ショートカット」「行の加工」の3節とする。「フォーカスモード」に編集／プレビュー切り替えのCtrl / Command + Enterと、フォーカスモード中のみ有効なことを記載する。
- 「リスト編集」以降の解説（リスト編集、全角Markdown補正、入力置換、補足）は表示しない。解説の削除によって既存の編集機能を変更しない。
- 解説内容は通常モードの入力フッターから開く入力支援と共通化する。
- モーダルにはせず、エディターを操作可能な状態で左領域内に表示する。
- 内容が画面の高さを超える場合は解説欄だけを独立してスクロール可能にする。
- 開閉状態は保存しない。

## 5. 中央領域

中央領域には現在選択しているタブ名、Markdown入力欄または第6章のMarkdownプレビュー、本文文字数を表示する。検索・置換UIは編集中だけ表示する。

- タブ名、検索・置換UI、本文shellを同じ編集列幅に揃え、外側中央領域の中で左右均等に配置する。
- 編集列はtextareaの左右paddingを含めて最大752pxとし、本文の折り返し幅は最大720pxを目標とする。本文paddingは481px以上で各16px、480px以下で既存の各13pxを維持する。縦スクロールバーがある場合はその幅だけ本文幅が小さくなる。
- 編集列は親の利用可能幅まで縮小できるものとし、最小幅を設けない。外側余白は768px以上で左右各20px、767px以下で左右各12pxとする。
- 解説・検索の開閉で編集列の幅や中心位置を変えない。タブ名は左上操作との衝突回避用の内側余白を優先する。
- フォーカス全体で1枚の静的な放射状グラデーションを共有する。中央をわずかに明るくし、基調色60%から四隅100%へ変化させる。本文shell・textarea・検索層・文字数は透明にし、解説ドロワーのsurfaceは維持する。
- 配色はNo.8の単色比較で採用した。ライトは中央#faf8f2／基調#f5f2ea／四隅#eeebe3、ダークは#151d2a／#111722／#0e131cとする。本文・補助文字・placeholder・検索強調は背景3色に対し4.5:1以上を確認した。
- フォーカス中のplaceholderはopacity 1、ダーク現在一致の背景はrgb(251 146 60 / 56%)とする。テーマ選択は既存設定へ従う。PR-18以降は通常モードも同じページ背景・検索色を共有する（通常モードのパネルと枠は維持）。強制色モードではグラデーションを外しシステム色へ従う。画像・アニメーションは追加しない。
- フォーカスモード中はtextareaへフォーカスしても、通常モードのフォーカス用アウトラインを表示しない。
- 中央領域ではタブ名の下の区切り線だけを表示し、中央パネルとtextareaの枠線は表示しない。

### タブ名

- 中央領域上部に固定し、textareaのスクロールでは移動しない。
- 現在選択しているMarkdownタブ名を表示する。
- ダブルクリックで編集を開始し、前後の空白を除いた1〜30文字をEnterまたはフォーカス離脱で確定する。
- Escapeキーで変更前の名称へ戻す。タブ名編集中のEscapeキーではフォーカスモードを終了しない。

### エディター

- フォーカスモードの本文と検索ハイライト層は、自己ホストのNoto Sans JP 400（normal）を共有する。PR-18以降は通常モードの入力本文と検索層も同じ書体とし、タブ名、検索UI、通常モードのプレビュー・変換結果の書体は維持する。
- フォールバックは `"Hiragino Kaku Gothic ProN", "Yu Gothic", Meiryo, sans-serif` の順とする。フォント未対応の文字と絵文字にはブラウザ・OSの代替書体を使用する。
- フォントは同一オリジンから必要時に読み込み、外部CDNや本文に応じた外部要求は使用しない。読込中・失敗時にも代替書体で本文を表示し、入力を継続できる。
- フォント読込の完了・失敗後は、表示中の検索の現在一致を必要に応じて再び可視範囲へ移し、ハイライト層のスクロールを合わせる。本文、カーソル、選択範囲、フォーカスは変更しない。
- 英数字はプロポーショナルとなり、コード・表の空白による見かけの位置合わせは等幅と異なる。原文の空白・タブは維持する。textarea内のコードだけ別書体にはしない。
- 本文サイズは `1.125rem`（ルート16pxで18px相当）とする。PR-12で16・17・18px相当を比較して採用した。
- 採用値は画面幅で縮小せず、本文・プレースホルダー・検索ハイライト層で共有する。ルートfont-sizeを固定せず、ブラウザの文字サイズ設定とズームを尊重する。タブ名・操作・検索UI、通常モードと右ペインには本文サイズを継承させない。
- 本文・プレースホルダー・検索ハイライト層は行高1.8、字間0.02emを共有する。No.4の5案比較で採用した。コード・表を含む全文へ適用し、原文へ空白・改行を追加しない。通常モードの行高1.65・字間normalは維持する。

- 段落間は原文の改行・空行と行高1.8で表現する。段落だけに18pxの追加余白は設けない（希望仕様は保留）。空行の自動挿入・圧縮・段落判定・保存時整形は行わず、コード・リスト・引用内と末尾の空行も維持する。
- 現在選択中のタブに接続された既存のtextareaをそのまま使用する。
- 既存の入力支援、変換、保存、永続化処理を変更しない。
- 入力置換は通常モードと同じ全体設定とルールを使用し、同じtextareaの入力イベント経路で実行する。
- 全角Markdown補正は通常モードと同じ設定を使用し、ONの場合だけ同じtextareaの入力イベント経路で実行する。
- 検索アイコンは表示しない。検索・置換UIは `Ctrl + F` / `Command + F` と `Ctrl + H` / `Command + Option + F` で開き、タブ名とtextareaの間に表示してtextareaへ重ねない。
- 検索中のEscapeは検索・置換UIだけを閉じ、フォーカスモードを終了しない。
- フォーカスモード中は既存設定にかかわらずtextarea内部だけをスクロール対象とする。保存済みの内部スクロール設定値は変更しない。
- textareaの下に編集列幅と揃えた固定フッターを設け、右寄せで「本文 N文字」を表示する。原文のUnicodeコードポイント数とし、Markdown記号・空白・改行・タブも含む。結合文字・複合絵文字は見た目の1文字と一致しない。通常モードと同じ既存集計を用い、変換待機に依存しない。
- フォーカス中のフッターは文字数だけとし、検索・入力支援ボタンは表示しない。補助文字サイズ0.82remとテーマのmuted色を使い、本文へ重ねない。
- count要素の既存IDをtextareaのaria-describedbyで参照する。記号・空白・改行を含む説明を読み上げ用に添え、フォーカス中はaria-live=offとする。通常モードのpoliteは維持する。
- 別タブへの切り替え、タブの追加、削除、復元、完全削除はできない。

## 6. 右領域とプレビュー切り替え

右領域は空白とし、編集／Markdownプレビュー切り替え用のアイコンボタンは表示しない。

- ショートカットで中央の本文領域を編集／プレビューに切り替える。同時には表示しない。タブ名・文字数・左側操作は維持する
- 初期表示とフォーカスモード再開始時は編集とする。表示状態を保存しない
- プレビューには既存の解析結果と安全なMarkdownレンダラーを再利用する。切り替え時は待機中の解析を確定し、直前の入力を反映する。失敗時は古い結果の代わりにエラーを表示し、原文を保持する
- プレビューは編集列と同じ最大752px幅で内部スクロールする。本文の書体・サイズ・行間・字間はフォーカス入力と揃え、見出し・コード・表などは既存プレビューの意味表現を維持する。文末の入力専用下余白は付けない
- textarea DOMとレイアウト枠を保持し、visibility:hiddenとinertで操作・表示を隠す（Firefoxの標準Undoを失うdisplay:noneを入力には使わない）。編集へ戻る際は選択範囲とスクロール位置を復元してフォーカスする。プレビューへ切り替える際はプレビュー領域へフォーカスする。プレビュー自身のスクロール位置も同じセッション内で保持する。高さ変更による丸めは許容する
- 検索・置換UIはプレビュー中に隠す。検索・置換ショートカットは編集へ戻って既存UIを開く。表示切り替えでは検索語を消去しない
- プレビュー中も通常のEscapeでフォーカスモードを終了し、最後の編集位置を復元する。タブ名編集やツールチップ等のEscape処理は従来どおり優先する
- プレビューと入力のスクロール同期、変換結果、形式選択、コピー、警告は追加しない

切り替えキーは `Ctrl + Enter` / `Command + Enter` を採用する。フォーカスモード内のみで有効とし、IME変換中、他の操作が処理済みの場合、キーリピートでは切り替えない。Shift・Altを併用しない。通常モードとフォーカスモードで共通の入力支援に案内する。
提案された `Shift + Escape` はChrome・Edgeのタスクマネージャと競合するため利用者回答で推奨代替を採用し、アプリのモード切り替えには割り当てない。通常のEscapeも修飾キーなしの場合だけモードを切り替える。
公式確認：[Chrome](https://support.google.com/chrome/answer/157179)、[Edge](https://www.microsoft.com/en-us/edge/learning-center/how-to-use-edge-task-manager)。

## 7. 非表示にする機能

フォーカスモード中は次の機能を非表示にする。

- 通常ヘッダー
- 通常モードの右ペイン（Markdownプレビューと変換結果）
- 変換形式選択とコピー
- 設定とアプリ情報
- 通常のタブ一覧、タブ切り替え、追加、削除、削除済み一覧
- PC用の左右ペイン区切り
- 狭い画面用の入力・変換結果切り替え
- 出力文字数、変換警告、通常画面の通知

編集ツールバーは追加しない。

## 8. フォーカスモードの終了

次の操作で通常モードへ戻る。

- 左上の「×」アイコンを押す。
- タブ名を編集中でない状態でEscapeキーを押す。

終了時は狭い画面用の表示ペインを入力へ設定し、終了直前のカーソル位置、選択範囲、textareaのスクロール位置を復元してエディターへフォーカスする。

## 9. 状態保持

モード切り替え前後で次の状態を保持する。

- 入力内容
- 終了直前のカーソル位置
- 終了直前の選択範囲
- 終了直前のtextareaのスクロール位置
- 選択中のタブ
- textareaのブラウザ標準Undo/Redo履歴

状態保持のため、モード切り替え時にtextareaコンポーネントとtextarea DOMを再生成しない。
幅の変更で折り返しとスクロール可能範囲が変わるため、scrollTopは変更後の範囲へ丸められる場合がある。

## 10. 再読み込み時の扱い

- フォーカスモード、編集／プレビューの選択、プレビュー位置、解説欄の開閉状態はLocalStorageへ保存しない。
- ページを再読み込みした場合は通常モードで表示する。
- 入力内容、タブ情報、アプリ設定など、既存の永続化対象はこれまでどおり保持する。

## 11. 767px以下の表示

既存のレスポンシブ用ブレークポイントである767px以下では次の表示とする。

- PC用の左領域と右領域は通常配置しない。
- 中央領域を全幅表示する。
- 「×」、「？」アイコンは画面左上へ横並びで固定する。検索・プレビュー切り替えアイコンは表示しない。
- 「？」アイコンを押すと、解説欄を画面左端から重ねるドロワーとして表示する。
- ドロワーを表示してもエディターは操作可能とし、モーダルやフォーカストラップにはしない。
- ドロワー内容が画面の高さを超えた場合は、ドロワー内だけをスクロール可能にする。
- エディターとタブ名の機能はPC表示と同じとする。

## 12. 文末の下余白（No.6、PR-19）

2026-10-15の利用者回答により、No.6は「下余白を作り、手動で最終行を上端まで送れる形」を採用する。

- フォーカス中はtextarea内の原文の最終行より下に表示用の余白を設ける。文末まで手動スクロールすると、最終の表示行の行ボックス上端がtextareaの上padding位置に来る
- 下paddingは `max(通常の下padding, textarea表示高 - 上padding - 本文行高)` とし、textareaと検索ハイライト層で同じ値を共有する。本文・改行・空白・文字数・保存内容は変更しない
- 空文書と1表示行の短文はもともと上端にあり、不要な1画面分の空スクロールを追加しない。原文末尾にLFがあれば、その後の空の最終行まで上端へ送れる
- 対象高はタブ名・検索UI・文字数フッターを除いた本文の表示高とする。リサイズ、検索・置換開閉、文字サイズ変更、画面高変更に追従させる
- 入力・クリック・矢印・待機・モード開始時の独自の自動スクロールは追加しない。既存の検索一致移動とブラウザ標準のキャレット可視化は継続する。入力後も利用者が手動で位置を選べる
- 切り替えボタン・保存設定は追加せず、フォーカス中は常に適用する。通常モードでは元のpaddingへ戻す。同じtextarea DOMと既存の編集・IME・Undo/Redo経路を維持する
- モード終了や高さ変更でscrollTopが新しいスクロール範囲を超えた場合はブラウザの丸めを許容する
- キャレット座標の計測・全文ミラー・操作履歴による行判定は行わない。PR-17の精度・全文計測性能の条件は旧自動中央追従案の採用条件であり、本方式には用いない

本文高が通常の上下paddingと1行の合計より小さい場合は最小paddingを優先し、上端との一致を保証しない。
通常モードの文末余白や、自動で現在行を中央・上端へ固定する機能は対象外とする。
