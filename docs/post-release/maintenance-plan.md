プレーンテキストで文章構造を読み取れる状態を維持しながら、構造記号だけで境界を
判別できるブロック間の不要な空行を削減する。

### 対象範囲

- プレーンテキストConverterのトップレベルブロック間の区切り
- 見出し、段落、リスト、引用、コードブロック、テーブル、水平線、生HTMLの組み合わせ
- 変換仕様とConverter単体テスト

### 対象外

- 各ブロック内部の改行と空行
- Slack、Backlog Markdown、Backlog記法の変換
- Parserと中間表現
- 変換結果欄の表示スタイル
- 改行方法を選択するユーザー設定
- PR-1からPR-6の実装

### 完了条件

- トップレベルブロック間は原則として改行1つで区切られる
- 段落同士、および見出し以外のブロックから見出しへ移る境界は1行の空行で区切られる
- 連続する見出し同士は改行1つで区切られる
- 見出しの直後には、後続ブロックがある場合でも余分な空行を追加しない
- 引用、コードブロック、緩いリストに含まれる空行は維持される
- 出力の先頭と末尾へ余分な空行を追加しない
- 既存の変換内容と警告に意図しない差分がない
- `npm run lint`、`npm run type-check`、`npm run test`、`npm run build` が成功する

## 保留中のマイルストーン：PR-1 変換結果の情報保持

PR-6を単独で実施するため一時保留し、PR-6完了後に再開する。

### 目的

対応済みMarkdownを変換した際に、区切り文字の衝突、表構造の破損、脚注本文の欠落で
利用者の情報が失われる問題を解消する。

### 対象範囲

- Slackのインラインコードとコードブロックについて、内容と衝突しない表現または
  意味を維持するフォールバックを定義する
- Slackでリンクタイトルなどを表現できない場合の警告方針を再確認する
- Backlog Markdownの表セル内にあるインラインコードのパイプを安全に出力する
- 脚注参照と脚注定義を一組として扱い、定義本文を失わない代替表現と警告を定義する
- 対応する変換仕様、Parser・Converterの回帰テスト、実装を更新する

SlackとBacklog固有記法は、実装前に各サービスの公式仕様と再照合する。現行仕様と
公式仕様に差異がある場合は、コードより先に差異と影響範囲を報告する。

### 対象外

- PR-2以降の候補
- 新しい出力形式、外部APIへの投稿、サーバー保存
- 変換画面のUI刷新
- 脚注記法をネイティブ対応していない変換先への独自記法追加
- 関連しないParser・Converterのリファクタリング

### 実施順序

1. 最小入力で各問題を再現し、現行仕様との一致または差異を記録する
2. `../specs/conversion-rules.md` にフォールバック、情報保持、警告内容を定義する
3. 失敗する回帰テストをParserと対象Converterへ追加する
4. 仕様で定義した最小範囲だけを実装する
5. lint、型チェック、単体テスト、ビルドを実行する
6. SlackとBacklogの実画面へ貼り付け、表示結果と警告内容を確認する

### 必要なテスト

- 1個以上のバッククォートを含むSlackインラインコード
- 3個以上の連続バッククォートを含むSlackコードブロック
- タイトル付きリンクなど、Slackで情報を保持できない入力の警告
- パイプを含むインラインコードを置いたBacklog Markdown表
- 脚注参照が1件・複数件・参照なし定義の場合の本文保持と警告
- 日本語、改行、他のインライン要素を組み合わせた回帰ケース

### 完了条件

- PR-1AからPR-1Cの再現入力で、本文または表構造が暗黙に失われない
- 変換先で直接表現できない情報は、代替テキストまたは警告で利用者に示される
- 変換仕様とテストが実装結果に一致している
- `npm run lint`、`npm run type-check`、`npm run test`、`npm run build` が成功する
- SlackとBacklogの手動確認結果、未確認範囲が記録されている
