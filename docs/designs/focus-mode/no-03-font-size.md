# No.3 フォントサイズの調整 設計書

作成日：2026-10-15／優先度：高／状態：検討案・未実装

## 1. 目的と対象範囲

フォーカスモードの本文サイズを読みやすい大きさへ調整する。PC・タブレットを中心に
評価し、狭い画面でも本文が小さくならないようにする。ユーザーがサイズを選ぶ設定UIや
文書ごとのサイズ保存は対象外。

## 2. 現状

textareaと検索ハイライト層は `src/style.css` で `font-size: 0.95rem` を指定している。
ルート16pxなら15.2px相当で、通常・フォーカス両モードに共通して適用される。
フォーカスモード専用の本文サイズはない。

## 3. 推奨仕様

- フォーカスモードの本文は `1.125rem` とする。ルート16pxの環境で18px相当となる。
- PC・タブレット・モバイルで同じ指定を使用し、画面幅による本文サイズの縮小は行わない。
- ブラウザの文字サイズ設定とズームを尊重し、ルートのfont-sizeは固定しない。
- タブ名、操作ボタン、検索入力、文字数表示には本文サイズを継承させず、既存または各No.の指定を使う。
- プレースホルダーと検索ハイライトの文字組みは本文と一致させる。
- 通常モードと右ペインの本文サイズは現行値を維持する。

18pxは候補値であり、実測前に最適と断定しない。比較は16、17、18px相当で行い、
18pxを初期採用案とする。採用値を変える場合は、仕様とこの文書を先に揃える。

## 4. 実装設計

- `src/style.css` のフォーカスモード配下に本文サイズ変数を定義する。
- textareaと検索ハイライト層の両方が同じ変数を参照する。
- 親の `.editor-panel` 全体のfont-sizeを変更する方法は、操作UIまで拡大するため使用しない。
- 本文幅・折り返しはNo.1、書体はNo.2、行高はNo.4の設計と組み合わせて確認する。
- No.6の計測用DOMは実textareaのcomputed styleを読むため、18pxをJavaScriptへ重複定義しない。
- サイズ変更で本文の行数とscrollHeightが変わる。モード切り替えは既存の位置復元を利用し、
  textarea DOM、本文、selectionStart/Endを維持する。

新規JavaScript処理、依存、設定状態、保存項目は追加しない。

## 5. 変更予定ファイルと仕様更新

| ファイル | 内容 |
| --- | --- |
| `src/style.css` | 本文サイズ変数とフォーカス限定の適用 |
| `docs/specs/focus-mode-spec.md` | 本文サイズ、対象要素、文字サイズ設定の尊重 |
| `docs/post-release/maintenance-plan.md` | 当該No.の対象範囲、対象外、完了条件 |

Converter、Parser、自動保存、通常モードのCSSは対象外。

## 6. 検証と受け入れ条件

| 確認条件 | 期待結果 |
| --- | --- |
| PC 1280、1440、1920px | 既定設定で本文が18px相当になり、読み書きしやすい |
| タブレット768、1024px・縦横向き | 本文と操作が欠けず、横スクロールを強制しない |
| モバイル320、390px | 18px相当を維持し、既存の折り返しで入力できる |
| ズーム200%、ブラウザ文字サイズ変更 | 本文が追従し、タブ名やボタンと重ならない |
| 日本語・英数字混在、長いURL、絵文字、空行 | 行の欠けがなく、検索ハイライト位置が一致する |
| モード切り替え、検索、IME、Undo/Redo | 本文と選択が維持され、入力操作が継続できる |

Chrome、Edge、Firefox、Safariの対象環境で確認する。CSS値を写すだけの単体テストは
追加せず、実ブラウザでcomputed styleと表示を確認する。実装時はlint、型チェック、
既存テスト、ビルドを実行する。

## 7. 着手条件と依存関係

No.1の本文幅を基準に比較する。No.2の採否確定後に最終評価することを推奨するが、
サイズ単独の実装は可能。No.4の行高1.8を組み合わせると既定行高は32.4pxとなるため、
表示行数が減ることも比較する。実装前に現行仕様と実装計画を更新する。
