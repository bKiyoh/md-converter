# No.3 フォントサイズの調整 設計書

作成日：2026-10-15／優先度：高／状態：PR-12で比較・採用・対象実装と開発環境の検証済み（実機検証は残件）

## 1. 目的と対象範囲

フォーカスモードの本文サイズを読みやすい大きさへ調整する。PC・タブレットを中心に
評価し、狭い画面でも本文が小さくならないようにする。ユーザーがサイズを選ぶ設定UIや
文書ごとのサイズ保存は対象外。

## 2. 変更前の状態

textareaと検索ハイライト層は `src/style.css` で `font-size: 0.95rem` を指定している。
ルート16pxなら15.2px相当で、通常・フォーカス両モードに共通して適用される。
480px以下では両者が0.9rem（既定16pxで14.4px）へ縮小する。フォーカスモード専用の本文サイズはない。

## 3. 推奨仕様

- フォーカスモードの本文は `1.125rem` とする。ルート16pxの環境で18px相当となる。
- PC・タブレット・モバイルで同じ指定を使用し、画面幅による本文サイズの縮小は行わない。
- ブラウザの文字サイズ設定とズームを尊重し、ルートのfont-sizeは固定しない。
- タブ名、操作ボタン、検索入力、文字数表示には本文サイズを継承させず、既存または各No.の指定を使う。
- プレースホルダーと検索ハイライトの文字組みは本文と一致させる。
- 通常モードと右ペインの本文サイズは現行値を維持する。

16・17・18px相当を比較し、18px相当（1.125rem）を採用した（第8章）。
読み書き速度や疲労を測った結果ではなく、開発環境での表示比較による採用判断である。

## 4. 実装設計

- `src/style.css` のフォーカスモード配下に本文サイズ変数を定義する。
- textareaと検索ハイライト層の両方が同じ変数を参照する。
- 親の `.editor-panel` 全体のfont-sizeを変更する方法は、操作UIまで拡大するため使用しない。
- 本文幅・折り返しはNo.1、書体はNo.2、行高はNo.4の設計と組み合わせて確認する。
- No.6の計測用DOMは実textareaのcomputed styleを読むため、18pxをJavaScriptへ重複定義しない。
- サイズ変更で本文の行数とscrollHeightが変わる。モード切り替えは既存の位置復元を利用し、
  textarea DOM、本文、selectionStart/Endを維持する。

新規JavaScript処理、依存、設定状態、保存項目は追加しない。

## 8. 比較結果と採用判断（2026-10-15、本体実装前）

macOS 14.5 arm64、Chromium 148.0.7778.96・Firefox 150.0.2・Playwright WebKit 26.4で比較した。
No.1の本文幅、No.2のNoto Sans JP 400、行高1.65、字間normalを固定し、1・1.0625・1.125remを
実アプリの本文・検索層だけへ一時適用した。本文は日本語長文、句読点、英数字、全半角記号、
絵文字、コード、表、リスト、長いURLと空行を含む同一原文とした。

- [ライト比較（左から16、17、18px相当）](assets/no-03-size-comparison-light.png)
- [ダーク比較（同順）](assets/no-03-size-comparison-dark.png)

| 観点（既定16px基準） | 16px相当 | 17px相当 | 18px相当 |
| --- | ---: | ---: | ---: |
| 指定 | 1rem | 1.0625rem | 1.125rem |
| 行高（倍率1.65を維持） | 26.4px | 28.05px | 29.7px |
| 本文720pxの全角字数目安 | 45字 | 約42字 | 40字 |
| 1440×1060px画面の表示行数目安 | 34行 | 32行 | 30行 |
| 320px画面・本文270pxの全角字数目安 | 約16字 | 約15字 | 15字 |
| 320/390/768/1024/1440pxでのページ横はみ出し | なし | なし | なし |

字数はChromiumの「文」1文字のCanvas幅から算出し、禁則・混植を含む実際の折り返し字数を
保証しない。表示行数はChromiumのtextarea高946pxから上下padding32pxを除いた算出値で、
検索UIを閉じた比較条件。画面高や検索表示で変わる。

18px相当は両テーマで日本語・英数字・約物を大きく読み取れ、本文幅720pxで40字程度を保てる。
16px相当より表示行数が約12%減ることと、狭い画面の折り返し増加を受け入れ、初期推奨値の
1.125remを採用する。17pxは表示量との中間案だが、本文を大きくする目的を優先した。
全条件で原文を維持し、コード・表の構造記号を確認した。長いURLは既存の折り返しで表示する。
読みやすさは開発環境の目視評価であり、全利用者に最適、実機確認完了とは断定しない。

本体へ適用する前に、現行仕様とPR-12の計画へ採用値を確定した。行間・字間の独立変更は行わず、
サイズに伴う計算済み行高の増加だけを許容する。No.4の行高1.8の試作・採用は今回行っていない。

## 9. 実装後の検証と残件（2026-10-15）

- `--focus-editor-font-size: 1.125rem` をフォーカス本文と検索層で共有した。プレースホルダーにも同じサイズが適用され、480px以下の既存0.9remより優先される。親パネル・ルートのサイズは変えていない
- Chromium・Firefox・WebKitで320/390/480/767/768/1024/1280/1440/1920pxを確認。768×1024と1024×768の両向きで本文・操作を表示でき、全幅で18px相当、横はみ出しなし。通常モードと出力欄は15.2px相当へ戻る
- 日本語・英数字・絵文字・長いURL・表・コード・リスト・空行を含む長文で、本文と検索層の内幅・scrollHeight・手動スクロール位置が一致した。独立Rangeとの差は通常・拡大・ズーム相当を通じて最大0.001px未満。現在一致は検索時に可視範囲へ移る
- Chromiumは起動オプション `--blink-settings=defaultFontSize=20`、Firefoxは `font.size.variable.x-western` / `font.size.variable.ja` を20に設定し、ルート20px・本文22.5pxを確認した。3エンジンでルート20pxの一時CSSによる拡大も検証した。WebKitの実際の文字サイズ設定は未確認
- 720×450 CSSビューポートで1440×900の200%ズーム相当の再配置を確認。検索・置換表示中も本文高250px以上を維持した。実際のブラウザズームは未確認
- 同じtextarea DOM、本文・手動選択・復帰時フォーカス、検索・置換開閉、長いタブ名を維持した。Chromium・WebKitはモード往復のUndo/Redoを保持。Firefoxは変更前CSSでもUndoできない既存PR-4を再現し、合格扱いにしていない
- CSS定数を写す単体テストは追加せず、既存全体テストとリポジトリ外のPlaywrightスクリプトで検証した。新規依存・設定・保存項目・JavaScript処理の追加はない
- `npm run lint`、`npm run type-check`、`npm run build`、`git diff --check` は成功。`npm run test` は520件成功、既存PR-3の2,000件ハイライトテスト1件が5秒でタイムアウトした。npm 12.2.0とNode.js 22.20.0の対応版警告は残る

比較・採用・対象実装と開発環境の検証を完了した。公開完了、全対象環境の受け入れ完了とは扱わない。
Windows、iPadOS、製品版Chrome・Edge・Safariと最低対応版、実際の200%ズーム、日本語IMEは未確認。
実機では文字サイズ設定、プレースホルダー・選択・検索の位置、入力・Undo/Redoをライト／ダークで確認する。
未確認環境とFirefoxの既存問題はPR-4、既存テスト失敗はPR-3へ残す。PR-8・PR-7・PR-6は保留を維持する。
次の改善対象はNo.4の行間・字間の比較・調整で、No.3から機能実装の持ち越しはない。
