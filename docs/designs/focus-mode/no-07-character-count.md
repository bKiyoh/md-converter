# No.7 本文文字数カウント 設計書

作成日：2026-10-15／優先度：中／状態：検討案・未実装

## 1. 目的と対象範囲

フォーカスモードでも現在選択中のタブの入力文字数を把握できるようにする。
既存の入力文字数を再利用し、エディター下部の控えめな表示だけを追加する。
出力文字数、全タブ合計、選択範囲の文字数、目標文字数、記法除去後の文字数は対象外。

## 2. 現状と仕様差分

- `src/utils/countCharacters.ts` は `Array.from(value).length` でUnicodeコードポイントを数える。
- `src/App.vue` は選択中タブの `markdown` から `inputCharacterCount` をcomputedで計算する。
- `MarkdownEditor.vue` は `characterCount` propを受け取り、通常モードのフッターで表示する。
- フォーカス中はフッターをtemplateとCSSの両方で非表示にし、textareaの `aria-describedby` も外す。
- `focus-mode-spec.md` 第5・7章は文字数非表示を明記している。

表示追加は現行仕様の変更となる。実装前に該当箇所を更新する。

## 3. カウントの定義

本No.の「本文文字数」は、既存と同じ**Markdown原文の入力文字数**とする。
見出し記号、強調記号、リンクURL、コード、半角・全角空白、改行、タブをすべて含む。
ParserやプレーンテキストConverterを経由せず、不完全なMarkdownでも同じ規則で数える。

| 入力 | 文字数 | 補足 |
| --- | ---: | --- |
| 空文字 | 0 | 初期表示も0文字 |
| `日本語😀` | 4 | サロゲートペアの絵文字は1コードポイント |
| `**太字**` | 6 | 強調記号を含む |
| `# 日本語\n😀` | 7 | 記号・空白・LFを含む |
| `a\nb` | 3 | LFは1文字 |
| ` \t　` | 3 | 半角空白・タブ・全角空白 |
| `e` + 結合アクセントU+0301 | 2 | 見た目の1字と異なる |
| `👨‍👩‍👧‍👦` | 7 | ZWJを含む複合絵文字は7コードポイント |

これは書記素クラスタ数ではない。日本語の通常の仮名・漢字は原則各1として数えるが、
結合濁点や異体字セレクターは別に数える。見た目の1文字と一致すると説明しない。
Stringの反復がコードポイント単位になることは
[ECMAScript仕様](https://tc39.es/ecma262/multipage/text-processing.html#sec-string.prototype-@@iterator)
を参照。既存の数え方を維持する判断であり、Intl.Segmenterや新規ライブラリは導入しない。

入力値の改行をカウント前に変換しない。textareaの通常入力ではLFになるが、状態値に
CRLFがある場合は既存関数どおり2コードポイントとして数える。

## 4. 表示・アクセシビリティ

- textareaの下に固定のフッター行を置き、右寄せで「本文 1,234文字」と表示する。
- textarea内部と一緒に流れず、本文やキャレットへ重ねない。フッター高は通常行高で約24pxを目安とする。
- サイズは既存の `0.82rem` を基準に、No.3の18pxは適用しない。
- 色はテーマのmutedを利用し、背景とのコントラスト4.5:1以上を確認する。透明度で薄くしない。
- 編集列の幅はNo.1と共有する。単独導入する場合は既存の親幅へ従う。
- フォーカス中はフッターの検索・入力支援ボタンを非表示のままとし、文字数だけを表示する。
- `markdown-input-count` の既存IDを再利用し、textareaから `aria-describedby` で参照する。
- 「Markdown記号・空白・改行を含む入力文字数」という説明をスクリーンリーダー向けに添える。
- 入力のたびの読み上げを避けるため、フォーカス中のカウントに `aria-live="off"` を適用する。
  通常モードの既存の読み上げ挙動は維持する。

## 5. 実装設計と変更予定ファイル

| ファイル | 内容 |
| --- | --- |
| `src/components/editor/MarkdownEditor.vue` | 既存フッターの表示条件を変更し、ボタン群だけをモードで隠す。既存count要素を共有 |
| `src/style.css` | フォーカス中フッター全体を隠す指定を置き換え、文字数用配置を指定 |
| `tests/unit/components/editor/MarkdownEditor.spec.ts` | 表示、ボタン非表示、説明IDを検証 |
| `tests/unit/utils/countCharacters.spec.ts` | 既存定義の境界ケースを追加 |
| `tests/integration/App.spec.ts` | 選択中タブとの連動、入力・置換・モード往復を検証 |
| `docs/specs/focus-mode-spec.md`、`docs/specs/product-spec.md` | 表示対象とカウント定義 |

Appの既存computedとpropをそのまま使い、2つ目の集計処理・Parser呼び出し・Converter呼び出しを
追加しない。count要素をモード別に複製せず、IDの重複を防ぐ。
入力・貼り付け・置換・Undo/Redoで既存markdownが更新される経路に追従し、150msの変換待機に依存しない。
IME中は既存の原文状態に反映された範囲を数え、確定後には必ず確定値へ一致させる。
新規状態、設定、保存項目、依存は追加しない。

## 6. 検証と受け入れ条件

- 前述の入力例に加え、末尾改行、CRLF、不完全なMarkdownを単体テストで確認する。
- 通常モードで別タブを選び、フォーカスへ入るとそのタブだけの文字数になる。
- 入力、削除、貼り付け、全置換、Undo/Redoで表示が更新され、空なら0文字になる。
- 変換の待機中や解析失敗時も原文の文字数を表示できる。
- フォーカス中は文字数だけが下部にあり、検索・入力支援の通常ボタンが現れない。
- 同じDOM IDは1つだけで、textareaの説明参照先が存在する。
- 320px、768px、PC、200%ズーム、ライト・ダークで本文や最終行を覆わない。
- No.6導入済みなら、フッターを除いたtextareaの高さで中央位置と下余白を再計測できる。
- 実IME、スクリーンリーダー、タブ移動、モード往復は実ブラウザで確認する。
- 実装時はlint、型チェック、単体・結合テスト、ビルドを実行する。

## 7. 着手条件と残る判断

他のNo.なしでも導入できる。実装前に非表示仕様を更新し、独立したマイルストーンを定義する。
記法除去後の文字数や書記素クラスタ単位を求める場合は、通常モードとの統一を含む別の製品判断とする。
