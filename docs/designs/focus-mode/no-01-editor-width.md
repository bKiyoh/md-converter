# No.1 エディタの横幅調整 設計書

作成日：2026-10-15／優先度：高／状態：実装・幅検証完了（既存操作課題・実機確認は別途残る）

## 1. 目的と対象範囲

フォーカスモードの本文を中央へ配置し、デスクトップとノートPCで文章の横方向の
視線移動を抑える。幅と余白だけを対象とし、フォント、行間、背景は別のNo.で扱う。

## 2. 現状と現行仕様との差分

- `src/style.css` の `.app--focus-mode .app-content` は3列Gridで中央領域を配置する。
- 中央領域は960pxを基準とし、広い画面では最大1680pxまで拡大する。
- `.editor-panel` の左右paddingはPCで20px、767px以下で12px。
- textareaと検索ハイライト層は481px以上で左右に16pxずつ、480px以下では13pxずつpaddingを持つ。
- 現状は中央領域の拡大に伴い、本文の折り返し幅も拡大する。

採用前の `focus-mode-spec.md` 第3章と保留中のPR-6は、広い画面で編集領域を広げる
方針である。利用者の720px案を中央領域そのものの幅へ適用すると、この方針と衝突する。
この差異を報告し、**外側の中央領域と内側の本文幅を分ける案**を採用する。
現行仕様とPR-10の計画を先に更新し、PR-6の外側領域の検証は保留のまま残す。

## 3. 推奨する表示仕様

- 外側の3列Grid、左右の操作領域、中央領域の幅は現行仕様を維持する。
- 中央領域の中で、タブ名、検索・置換UI、textareaを同じ幅へ揃える。文字数表示はNo.7で扱う。
- 本文の折り返し幅の上限は720pxを目標とする。
- textareaの左右padding（481px以上は各16px、480px以下は各13px）を含む編集列の上限は752pxとする。
- 編集列は `width: 100%`、`max-width: 752px`、左右marginをautoとする。
- 画面が狭い場合は親の利用可能幅まで縮小する。横幅の最小値は設けず、`min-width: 0` とする。
- 外側の余白は既存のPC各20px、767px以下各12pxを利用する。
- 解説の開閉で編集列の幅や中心位置を変えない。

目安はブラウザズーム100%、既定の文字サイズ、縦スクロールバー幅を除外した値である。
実際の本文幅はスクロールバー分だけ小さくなる場合がある。

| 画面幅 | 外側中央領域 | 編集列の上限適用後 | 本文幅の目安 |
| ---: | ---: | ---: | ---: |
| 320px | 320px | 296px | 270px |
| 767px | 767px | 743px | 711px |
| 768px | 768px | 728px | 696px |
| 960px | 960px | 752px | 720px |
| 1440px | 960px | 752px | 720px |
| 1920px | 1080px | 752px | 720px |
| 2560px | 1560px | 752px | 720px |

320pxの本文幅目安は、実測で既存の480px以下のpadding各13pxを確認し、初期案の264pxから270pxへ訂正した。
767/768px境界の15pxの本文幅差は、既存の外側paddingの切り替えによる。
境界で操作や本文が欠けないことを確認する。連続的な余白への変更が必要なら、実装前に
この値と対応仕様を更新する。

## 4. 実装設計

- `src/style.css` のフォーカスモード限定セレクターへ編集列の幅制約を追加する。
- タブ名、検索・置換UI、本文shellへ共通の幅変数を適用し、数値を重複管理しない。
- `.editor-panel` の縦方向flex構造を維持する。幅制限のためにtextareaを条件付きで再生成しない。
- タブ名の左余白は既存の固定操作ボタンとの衝突回避を優先する。特に320px、768pxで確認する。
- textareaと検索ハイライト層の内幅、padding、スクロールバー条件を揃える。
- `useFocusMode` の編集位置取得・復元経路をそのまま利用する。幅変更で行が折り返されるため、
  保存したscrollTopは新しいスクロール範囲に丸められる場合がある。本文・選択範囲は維持する。

新規コンポーネント、新規状態、保存項目、新規依存は追加しない。

## 5. 変更予定ファイルと影響

| ファイル | 変更内容 |
| --- | --- |
| `src/style.css` | 編集列の最大幅、中央配置、幅を共有するCSS変数 |
| `src/components/editor/MarkdownEditor.vue` | CSS適用先の識別が必要な場合だけクラス追加 |
| `docs/specs/focus-mode-spec.md` | 外側中央領域と本文幅を区別して記載 |
| `docs/specs/product-spec.md` | フォーカスモードの幅の要約を整合 |
| `docs/post-release/maintenance-plan.md` | PR-6との関係を整理して対象範囲を定義 |

通常モード、Converter、保存形式、入力支援は対象外。No.2〜4適用後も本文幅の定義を維持する。

## 6. 検証と受け入れ条件

- Chrome、Edge、Firefox、Safariで320、767、768、960、1440、1920、2560pxを確認する。
- 横に広い画面で本文幅が約720pxを超えず、左右の余白が均等になる。
- 解説・検索の開閉、長いタブ名、200%ズームで入力領域や操作が欠けない。
- 日本語長文、長いURL、コード、表、空行の折り返しと検索ハイライトが一致する。
- モード切り替え前後でtextarea DOM、本文、カーソル、選択、Undo/Redoが維持される。
- 通常モードへ戻した後、既存のペイン比率と右ペイン同期が利用できる。
- CSSの数値だけを確認する単体テストは追加せず、実ブラウザで幅と中心位置を計測する。
- 実装時はlint、型チェック、既存テスト、ビルドを実施する。

## 7. 着手条件と残る判断

720pxを「本文幅」とする整理を採用し、現行仕様と実装計画を先に更新した。
2026-10-15の今回の指示によりPR-8を保留し、PR-10としてNo.1だけを優先する。
PR-6は外側領域の改善・検証として残し、暗黙に完了扱いにしない。
720pxは採用した上限目標であり、書体比較や利用者評価で最適値と確定したものではない。

## 8. 実施結果と次の対象（2026-10-15）

- PR-10としてNo.1だけを実装した。`src/style.css` の共通CSS変数と幅制約を利用し、コンポーネント・新規状態・依存追加は不要だった
- Chromium、Firefox、Playwright WebKitで320、480、720、767、768、960、1100、1439、1440、1920、2560pxを計測し、編集列・本文幅、中央配置、解説・検索開閉時の幅維持を確認した
- 長いタブ名、日本語長文、長いURL、コード、表、空行、検索ハイライト、同じtextarea DOMと本文・選択範囲、通常モードのペイン比率と同期復帰を確認した
- lint、型チェック、ビルド、差分チェックは成功。全体テストは517件成功、既存のPR-3の1件だけタイムアウトした。CSS値だけの単体テスト追加はしていない
- Chromium・WebKitのUndo/Redoは確認した。FirefoxはUndo→Redoの後にモードを切り替えるとUndoが効かず、変更前CSSでも再現した。今回の回帰ではないが、仕様どおりのUndo保持を確認済みとはしない。PR-4へ記録した
- 実際の200%ズーム、製品版Chrome・Edge・Safari、最低対応版、実機IME・タッチなどは未確認。720×450 CSSビューポートでの再配置確認とは区別する
