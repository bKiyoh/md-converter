# No.4 行間・文字間隔の調整 設計書

作成日：2026-10-15／優先度：高／状態：検討案・未実装

## 1. 目的と対象範囲

フォーカスモードの本文の圧迫感を軽減し、日本語長文で視線を次の行へ移しやすくする。
textarea内のすべての文字と行を同じ設定にする。段落だけの余白はNo.5で扱う。

## 2. 現状

`src/style.css` のtextareaと検索ハイライト層は `line-height: 1.65`。
専用のletter-spacing指定はなく、ブラウザの通常値を利用している。
双方とも `white-space: pre-wrap`、`tab-size: 2`、`overflow-wrap: break-word` を指定している。

## 3. 推奨仕様

| 項目 | 初期採用案 | 意味 |
| --- | --- | --- |
| line-height | `1.8` | 本文サイズに追従する行高 |
| letter-spacing | `0.02em` | 本文サイズに追従する字間 |
| 段落だけの追加余白 | なし | No.5の制約と判断に従う |
| 適用先 | フォーカス中のtextareaと検索層 | 通常モードの文字組みを維持 |

No.3の18px相当と組み合わせた場合、行高は32.4px、字間は0.36px相当になる。
これは利用者提示値を出発点とした案であり、参考サイトの実測値ではない。
候補比較では行高1.7/1.8、字間0/0.02emを同じ本文・幅・フォントで確認する。

## 4. 実装設計

- フォーカスモード用の行高・字間変数を `src/style.css` に置き、textareaと検索層で共有する。
- 数値の行高を用いて、ブラウザの文字サイズ設定に追従させる。
- 入力値へ空白や改行を挿入して見た目を調整しない。
- コード、表、見出しにも同じ行高・字間を適用する。textarea内の部分装飾は追加しない。
- ハイライトのmark要素には独自のfont、padding、line-heightを追加せず、折り返しを一致させる。
- No.6のカーソル計測と既存の右ペイン同期はcomputed styleに基づく計測を利用し、
  JavaScript側へ1.8や0.02emを埋め込まない。
- textarea DOMと既存の編集イベント経路を維持する。

字間を広げることでコードやMarkdown表の表示幅も増える。変換結果・保存内容には影響しないが、
長い行を含む実用文書で評価し、読み取りに支障がある場合は字間0も比較して採用値を再検討する。

## 5. 変更予定ファイルと影響

| ファイル | 内容 |
| --- | --- |
| `src/style.css` | 行高・字間の変数とフォーカス限定指定 |
| `docs/specs/focus-mode-spec.md` | 行高・字間と適用対象 |
| `docs/post-release/maintenance-plan.md` | 対象範囲と完了条件 |

新規コンポーネント、パッケージ、設定保存は不要。
通常モード、プレビューの段落スタイル、Converterの改行仕様は変更しない。

## 6. 検証と受け入れ条件

- 同じ本文で、現行と候補の表示行数、行の追いやすさ、横方向の詰まりを比較する。
- 日本語の句読点、括弧、英数字、絵文字、タブ、連続空白、複数の空行を含める。
- コードフェンス、表、ネストしたリストの記号やインデントが読める。
- 長い検索一致、折り返し境界、末尾改行でtextareaと検索層がずれない。
- No.3と合わせて200%ズーム、文字サイズ変更、320/768/1440pxで欠けを確認する。
- ライト・ダーク、Chrome・Edge・Firefox・Safariで入力、IME、検索、モード往復を確認する。
- 行高が増えても既存のtextarea内部スクロールと編集位置復元が使える。

CSS指定の複製となる単体テストは追加しない。実ブラウザで行高と折り返しを確認し、
実装時はlint、型チェック、既存テスト、ビルドを実行する。

## 7. 着手条件と参考資料

No.1〜3の採用値を基準に最終評価する。実装前に現行仕様と実装計画を更新する。
No.5の段落余白とは区別し、行間の拡大だけで段落余白18pxを達成したとは扱わない。

利用者指定の[参考サイト](https://mount.jp/magazine/monex-dev-with-ai/)は2026-10-15に
本文・CSSを取得できなかった。実際の行間・字間・見た目との比較は未完了である。
