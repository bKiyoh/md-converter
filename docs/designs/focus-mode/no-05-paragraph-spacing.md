# No.5 段落間の余白調整 設計書

作成日：2026-10-15／優先度：高／状態：制約調査・方式の判断待ち・未実装

## 1. 目的と対象範囲

通常の行間と段落境界に差をつけ、文章のまとまりを把握しやすくする。
希望値は段落間の追加余白18px程度。ただし、Markdown原文、通常のtextarea、IME、
選択、ブラウザ標準Undo/Redoを維持することを前提とする。

## 2. 現状と技術的制約

現在の入力欄は1つのtextareaであり、検索時だけ表示専用のハイライト層を重ねている。
textareaの値はプレーンテキストで、内部の段落に対して `p + p` のようなCSSは指定できない。
これは[HTML標準のtextareaのデータモデル](https://html.spec.whatwg.org/multipage/form-elements.html#the-textarea-element)
と現在の構成を踏まえた判断である。

- `line-height` はすべての行へ適用されるため、段落境界だけを18px広げる方法にはならない。
- 原文へ空行を追加すると保存・コピー・変換・文字数・Undo対象が変わる。
- ハイライト層だけに余白を付けると、実際の文字・キャレット・クリック座標がずれる。
- ネイティブ文字を隠して別DOMへ余白付き本文を描画しても、textareaの選択とIME位置は追従しない。

したがって、**現在のエディター構造を維持したまま、段落だけに任意の18pxを追加する方式は採用できない**。
利用者提示案と既存のtextarea維持ルールの両立には、この制約がある。

## 3. 方式比較

| 方式 | 段落だけの18px余白 | 原文・編集操作への影響 | 判断 |
| --- | --- | --- | --- |
| 原文の空行とNo.4の行高を利用 | 不可。原文の空行分の間隔 | 原文とネイティブ操作を維持 | 今回の推奨代替案 |
| 原文へ空行を自動挿入 | 追加行数による近似だけ | Markdown、保存、文字数、Undoを変更 | 不採用 |
| 表示専用層だけにmargin追加 | 表示上は可能 | キャレット、検索、選択、IMEがずれる | 不採用 |
| textarea以外の編集基盤へ変更 | 可能性あり | 入力処理・選択・Undo・保存接続の再設計が必要 | 別途検討 |
| 右ペインのプレビューだけに余白追加 | 可能 | フォーカスモードではプレビューが非表示 | 本No.の解決にはならない |

## 4. 推奨する代替設計

- フォーカスモードでも原文にある改行・空行をそのまま表示する。
- No.4の行高1.8を利用して圧迫感を軽減する。
- 空行の自動追加、連続空行の圧縮、保存時の整形、段落の自動判定は追加しない。
- コードフェンス内、緩いリスト内、引用内の空行も原文どおり表示する。
- 18pxの段落余白を実現したとは扱わず、本No.の希望仕様は保留とする。

18px本文・行高1.8の場合、空行1行の行ボックスは32.4px相当になる。
これは通常の改行に追加する18pxの余白とは異なる。
空行を含まない文書に新たな段落間隔は生じない。

## 5. 変更予定ファイルと着手条件

推奨代替案を採る場合、本No.だけのアプリコード変更・新規依存・保存項目はない。
No.4の実装と検証結果を参照し、検討結果として記録する。

| 文書 | 採用判断後の更新内容 |
| --- | --- |
| `docs/specs/focus-mode-spec.md` | 原文の空行を尊重し、段落専用余白は追加しないこと |
| `docs/post-release/maintenance-plan.md` | 代替案採用または希望仕様保留を明記 |

任意の18px余白を必須とする場合は、textarea維持ルールとの調整が必要になる。
先に製品・エディター方式の判断と独立した計画を作成する。本設計からcontenteditable、
CodeMirror、Monaco、独自Undoの実装へ自動的に進まない。

## 6. 検証条件

代替案を採用する場合はNo.4の手動確認と合わせて以下を確認する。

| 入力例 | 期待する表示とデータ |
| --- | --- |
| `一行目\n二行目` | 単一改行をそのまま表示し、余分な空行を追加しない |
| `第一段落\n\n第二段落` | 原文の空行1行を維持する |
| 3行以上の連続空行、末尾改行 | 原文の行数を維持する |
| コード、リスト、引用中の空行 | Markdownの文脈による余白の追加・除去をしない |
| コピー、保存・再読込、Undo/Redo | 見た目調整を理由に原文が変化しない |
| 検索、IME、クリックによるカーソル移動 | 表示と入力位置が一致する |

本No.にアプリ変更がなければ新規テストとビルドは不要。No.4を実装した際の検証結果を
本No.の18px余白達成の証拠にはしない。

## 7. 未解決事項と参考資料

「段落だけ18px」を必須とするか、原文空行と行間の改善で進めるかが残る製品判断である。
今回の設計作業では判断を確定せず、実装を保留する。

利用者指定の[参考サイト](https://mount.jp/magazine/monex-dev-with-ai/)は2026-10-15に
本文・CSSを取得できず、段落間隔は未実測。18pxは利用者提示の候補値として扱う。
