# フォーカスモードの文字サイズ変更 設計・検証記録

作成日：2026-10-16／状態：PR-25〜29対象実装・開発環境検証完了（実機確認は残件）

## 1. 目的と今回の扱い

フォーカスモードを終了せず、読み書きしやすい本文サイズへ変更できるようにする。
初回は仕様検討と候補の整理を行い、続く実装指示によりPR-25へ着手した。
2026-10-16の利用者回答により、16・18・20・22・24px相当の5段階から選ぶ方式を採用した。
その後の実装指示により、Aaの配置・保存・状態保持も採用し、現行仕様と実装計画を更新した。

## 2. 実装前に確認した状態

- 現行仕様は `../../specs/focus-mode-spec.md` 第4〜6・9〜12章と
  `../../specs/product-spec.md` の共通書体・フォーカスモード・自動保存。
- 本文サイズは全画面幅で `1.125rem`（ルート16pxで18px相当）に固定されている。
  サイズ選択UIと保存項目はない。
- `src/style.css` の `.app--focus-mode .editor-panel` にある
  `--focus-editor-font-size` を編集欄、検索ハイライト層、フォーカスプレビューで共有する。
  文末の下余白もこの変数と行高から計算している。
- 左上は「×」「？」だけで、右領域は空白。通常の設定画面はフォーカス中に表示しない。
  文字数フッターは数字だけであり、ここへ操作を増やすと現行仕様の変更になる。
- 設定保存は `useAppSettings` と `md-converter:settings:v1`、保存失敗・再試行は既存経路がある。
- `MarkdownEditor.vue` にはフォント読込後の検索位置・スクロール再評価があるが、
  利用者の文字サイズ変更を受ける経路はない。

No.3・PR-12の「サイズ選択UIは対象外」は当時の作業範囲である。
今回の追加依頼は、その完了済み判断を変更せず、新しい機能候補として扱う。
現行仕様間で今回の検討を妨げる矛盾は確認していない。

## 3. 採用した操作とサイズ（PR-27：2px刻みの選択）

### 操作の配置

- 左上は「×」「？」とし、文字サイズ専用の「Aa」は右領域の右端上部へ固定する。
  共通の `IconButton` とツールチップを使用する。
- ラベル・ツールチップは「文字サイズ」。開閉状態は `aria-expanded`、対象は
  `aria-controls` で関連付ける。Aaの図柄は装飾とする。
- 押すとボタンの下へ右揃えで小さなパネルを表示し、左へ広げる。「文字サイズ」のラベルをselectへ関連付ける。
  保存・適用・直接入力・増減ボタン・補足説明文は設けない。
- 調整範囲は8〜24px相当、2px相当刻みの次の9段階とし、変更を編集／プレビューへ即時反映する。

| 選択肢の表示 | 内部の指定 | ルート16px時の行高（1.8） |
| --- | --- | ---: |
| 8px | 0.5rem | 14.4px |
| 10px | 0.625rem | 18px |
| 12px | 0.75rem | 21.6px |
| 14px | 0.875rem | 25.2px |
| 16px | 1rem | 28.8px |
| 18px | 1.125rem | 32.4px |
| 20px | 1.25rem | 36px |
| 22px | 1.375rem | 39.6px |
| 24px | 1.5rem | 43.2px |

- 初期値は現在と同じ18px相当とする。18px相当を選び直すことで標準へ戻せるため、
  独立したリセットボタンは追加しない。
- 選択後もパネルを開き、selectへフォーカスを残す。本文へ自動フォーカスしない。
- 表示値はルート16px基準の目安とし、実際のサイズはブラウザの文字サイズ設定とズームへ追従する。
  利用者の最新指示に従い、この補足は画面へ表示しない。

### 開閉とキーボード

- Aaの再押下、パネル外のクリック／タップ、Escapeで閉じる。
- 開いた際はselectへフォーカスする。Escapeで閉じる場合はAaへ戻す。
  外側のクリック／タップで閉じる場合はクリック先のフォーカスを妨げない。
- selectの候補一覧の標準操作を優先する。文字サイズパネルのEscapeでフォーカスモードまで終了しない。
- パネル内の操作を処理したキーは、フォーカスモードの切り替えへ重ねて適用しない。
  ツールチップ等とのEscape優先順位は既存の「処理済みを優先」へ合わせる。
- パネルはモーダルにせず、フォーカストラップを設けない。Tabで外へ移動でき、
  フォーカスがパネルとAaの外へ移ったら閉じる。
- 入力支援の解説と文字サイズパネルは同時に開かない。一方を開いたら他方を閉じる。
- フォーカスモード開始時は閉じる。終了時も閉じ、開閉状態は保存しない。
- 専用ショートカットは追加しない。ブラウザのズームキーはそのまま利用する。

## 4. 適用範囲と表示維持

- フォーカス中のtextarea、placeholder、検索ハイライト層、Markdownプレビューの
  本文基準サイズへ同じ値を適用する。編集中・プレビュー中のどちらからでも変更できる。
- プレビューの見出しと本文の大小関係、コードの書体、表の意味表現は既存のままとする。
  空表示・エラー表示もプレビュー領域のサイズ指定に従う。
- 行高1.8、字間0.02em、書体、本文幅の上限720pxは維持する。
  文字サイズに応じて実際の行高・字間・折り返し・表示行数は変わる。
- タブ名、検索・置換UI、解説、文字数、操作ボタン、通常モードの入力・プレビュー・
  変換結果には適用しない。画面幅によるサイズの自動縮小は行わない。
- ブラウザ文字サイズとズームへ追従するようremで指定し、ルートfont-sizeは固定しない。
- 本文、選択範囲、カーソル位置、検索語、現在一致の識別、Undo/Redo履歴を維持する。
  textarea DOMを再生成せず、valueの再代入や入力イベントの発火を行わない。
- サイズ変更自体ではキャレットや検索一致へ自動スクロールしない。変更前のscrollTopと
  scrollLeftを可能な範囲で維持し、範囲外はブラウザの丸めを許容する。
  折り返しが変わるため、同じ文章が同じ画面位置に残ることは保証しない。
- 非表示の編集欄、プレビュー、および復帰用に保持したスクロール値にも同じ原則を適用する。
  編集へ戻る際に古いサイズの範囲外の値を使って位置を飛ばさない。
- 描画後に検索ハイライト層のスクロール位置を編集欄へ合わせる。
  次／前の検索一致へ移る操作は、変更後の文字組みで位置を計測する。
- 文末の下余白は変更後のサイズと行高に従って再計算する。本文・改行は追加しない。

## 5. 保存

- 文書ごとではなく、全タブ共通のアプリ設定とする。
- `md-converter:settings:v1` に数値の `focusEditorFontSize` を追加する。
  保存値は8・10・12・14・16・18・20・22・24だけを許可し、描画時にremへ対応付ける。
- 選択直後に既存の設定保存経路へ渡す。通常モードへの復帰、再度のフォーカス開始、
  タブ切り替え、再読み込み後も選択値を保持する。
- 項目がない旧設定、不正な型、許可値以外は18へ補完する。
  他の有効な設定項目は維持し、設定キーの版や文書保存形式は変更しない。
- 読み込み・保存失敗は既存設定の扱いに合わせる。保存できなくても表示上のサイズ変更は継続する。
  失敗は既存の保存エラー状態へ集約し、通常モードの永続警告と再試行で確認・復旧できるようにする。
  フォーカス中の警告表示追加は今回含めない。
- フォーカスモード自体とパネル開閉は保存しない。再読み込み時は通常モードで開始する。

## 6. レイアウトと代替案

PR-29でAaを右領域の右端上部へ移す。終了と解説は左上に残し、狭い画面でも左右へ分ける。
中央の本文幅と中心位置は維持し、タブ名の左右へ衝突回避余白を確保する。
サイズパネルはAaの下へ右揃えで重ね、画面内へ収める。高さ不足時はパネル内をスクロールする。
以下の比較表はPR-25時点の記録で、現在の操作は第3章と現行仕様に従う。

| 案 | 利点 | 判断 |
| --- | --- | --- |
| Aaから5段階を選択 | 現在値・標準値が分かり、少ない操作で変更できる | 16・18・20・22・24px相当の5段階方式を利用者回答で採用。Aaの配置も続く実装指示で採用 |
| 小さく／大きくボタン | 1px相当ずつ調整できる | 今回は不採用。利用者は5段階選択を選択した |
| スライダー・数値直接入力 | 任意値を指定できる | 初回は見送り。値の入力と範囲処理を増やさない |
| 通常の設定画面だけに追加 | フォーカス左上にボタンが増えない | 今回は見送り。フォーカス中に操作を完結させる目的を優先する |

PR-25で採用した16〜24px相当の範囲は、現在の18pxを維持しながら、小さくする選択と複数の
拡大段階を提供する。24pxで全利用者に十分とする判断ではない。
開発環境でタブ名との衝突と短い画面の操作性を検証した（第9章）。実機での読みやすさは残件とする。
