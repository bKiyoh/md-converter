# 入力置換仕様

## 1. 目的

Markdown本文を直接入力したとき、ユーザーが登録した短い入力文字を別の文字列へ置き換える。Markdown記法のスニペット機能や、保存済み本文に対する検索・一括置換にはしない。

画面上の名称は「入力置換」、説明は「登録した文字を、入力時に別の文字へ置き換えます。」とする。

## 2. 適用対象

- 選択中タブのMarkdown本文を編集する既存のtextareaだけを対象とする。
- 通常モードとフォーカスモードで同じ全体設定とルールを使用する。
- タブ名、検索・置換欄、設定、ルール管理画面、その他のフォームには適用しない。
- 貼り付け、ドラッグ＆ドロップ、保存内容の復元、タブ切り替え、検索・一括置換、外部処理からの値設定には適用しない。
- Undo／Redoで復元された文字列には再適用しない。

## 3. 置換の契機と完全一致

全体設定と対象ルールがともに有効な場合だけ、1回の入力に対して1ルールを適用する。置換結果に一致する別ルールは続けて適用しない。

### IME入力

- `compositionstart` から `compositionend` までは置換しない。
- `compositionend` で今回確定したcomposition範囲全体が入力文字と一致した場合だけ、1回判定する。
- composition範囲の一部に一致するルールは適用しない。
- IME確定に使用されたEnterでは、改行とリスト継続を実行しない。
- 空のcomposition、キャンセルされて本文が変わらなかったcompositionは置換しない。

「左右」を1つのcompositionとして確定した場合、「右」のルールは適用しない。別々のcompositionとして「左」と「右」を確定した場合、後者の「右」は独立した入力として判定する。

### 直接入力

- 半角スペース、全角スペース、修飾キーなしのEnterを区切り操作とする。
- 区切りの直前で終わる有効ルールを探し、ルールの入力文字の直前が本文先頭、半角スペース、全角スペース、改行のいずれかである場合だけ適用する。
- 複数ルールが一致する場合は入力文字が最長のルールを1件だけ適用する。同一入力文字は重複登録できないため、同じ長さの競合は発生しない。
- 入力文字には内部の半角・全角スペースを含められる。途中のスペースでは未完成の長いルールを適用せず、後続の区切りで最長一致を判定する。
- 区切りとして入力したスペースまたは改行は保持する。

Enterでは、入力置換、改行、Markdownリスト継続の順に計算し、textareaへ1回の編集として反映する。

## 4. Markdownコード内

インラインコードとコードブロックでは置換しない。フェンス形式だけでなく、Markdownパーサーがコードブロックとして解釈するインデント形式も対象外とする。

判定には既存と同じremarkパーサーのmdast位置情報を使用し、Markdown全文に対する正規表現判定は行わない。閉じられていないバッククォートなど、GFM上でコードとして解析されない文字列は通常テキストとして扱う。

## 5. ルール

```ts
type InputReplacementRule = {
  id: string
  source: string
  replacement: string
  enabled: boolean
}

type InputReplacementSettings = {
  version: 1
  enabled: boolean
  rules: InputReplacementRule[]
}
```

- 初期状態は全体設定ON、ルールなしとする。
- ルールはアプリ全体で共通とし、最大100件とする。
- 大文字・小文字を区別する。
- 並べ替え、正規表現、動的文字列、履歴、回数集計、インポート・エクスポートは実装しない。

### 入力文字

- 登録時に前後の空白を除去する。
- 1〜50 Unicodeコードポイント、改行なしとする。
- 無効ルールを含め、同じ入力文字を重複登録できない。
- Markdown記法そのものを登録できない。

### 置換後文字

- 空白だけの値を除く1〜200 Unicodeコードポイント、改行なしとする。
- 前後の空白は値として保持する。
- Markdown構造や装飾を生成する内容を登録できない。

### Markdown記法の検証

登録値を既存と同じGFMパーサーで単独のMarkdown文書として解析する。paragraph配下の通常text以外のノードが生成される場合は登録を拒否する。

パーサーが不完全なMarkdownを通常textとして扱う場合があるため、`**`、`_`、バッククォート、`[]`など、Markdown記号だけで構成された入力文字は補助的な禁止リストでも拒否する。`C#`や`issue#123`のように通常textとして解析される単語は許可する。

エラー文言は次を使用する。

- 重複：`同じ入力文字がすでに登録されています。`
- Markdown：`Markdown記法として使用される内容は登録できません。`
- 上限：`置換ルールは最大100件まで登録できます。`

## 6. 設定画面

既存の設定ポップオーバーへ次を追加する。

- 「入力置換を有効にする」スイッチ
- 説明「登録した文字を、入力時に別の文字へ置き換えます。」
- 「置換ルールを管理」ボタン

管理ボタンでは設定ポップオーバーを閉じ、専用モーダルを開く。モーダルでは追加、有効・無効、入力文字と置換後文字の編集、削除を提供する。Escape、閉じるボタン、背景クリックで閉じ、設定ボタンへフォーカスを戻す。

## 7. 保存

`localStorage` の専用キー `md-converter:input-replacements:v1` へJSONで即時保存する。設定はタブ単位にしない。

読み込み時にversion、全体設定、配列、100件上限、各フィールド、IDと入力文字の一意性を検証する。不正値、JSON解析失敗、LocalStorage例外では初期状態へ戻し、画面上の編集は継続する。

## 8. Undo／Redo

置換範囲と区切り・リスト継続を可能な限りtextareaのネイティブ編集1回として適用する。ネイティブ編集が利用できない環境では`setRangeText`へフォールバックし、本文とカーソルを維持する。

ブラウザ標準Undo履歴の単位には実装差があるため、自動テストに加えて対応対象の実ブラウザで次を確認する。

- IME確定後の置換をUndo／Redoできる。
- SpaceとEnterを契機にした置換をUndo／Redoできる。
- Undo直後に再置換されない。
- 既存のショートカット、検索・一括置換、リスト継続のUndo／Redoに回帰がない。

## 9. テスト

- 直接入力、IME、Space、全角Space、Enter、カーソル位置
- 全体設定とルール単位の無効化
- 部分一致、最長一致、連続置換の防止
- 貼り付け、ドロップ、復元、タブ切り替え、検索置換の除外
- インラインコード、フェンス・インデントコードブロックの除外
- Markdown記法、重複、空文字、改行、文字数、100件上限の検証
- LocalStorageの保存・復元・破損値・例外
- 通常モードとフォーカスモード
- Enterによる既存リスト継続、Tab、ショートカット、検索・一括置換の回帰
