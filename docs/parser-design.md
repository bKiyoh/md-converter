# Markdownパーサー設計（Milestone 2）

## 採用結果

Markdown解析には `unified` 11、`remark-parse` 11、`remark-gfm` 4を採用した。文字列置換ではなくmdastを経由でき、GFMのテーブル、タスクリスト、打ち消し線を同じ構文木として扱えるためである。プロジェクトのESM設定とNode.js対応範囲で、型チェック、テスト、ビルドが実行できることも確認した。

mdastはConverterへ直接渡さない。`src/parser/normalizeMarkdownAst.ts` でMVP要素だけをアプリ用の `MarkdownDocument` へ正規化し、パーサー依存をこの境界に閉じ込める。

## 保持する構文情報

- 見出しレベル、段落、引用、水平線
- 太字、斜体、打ち消し線、インラインコード、リンク
- リストの順序種別、開始番号、疎密、入れ子、チェック状態
- コードブロックの本文、言語、メタ情報
- テーブルのヘッダー、行、セル内インライン要素、列配置
- ソフト改行と明示的な改行の区別
- 警告位置に利用する開始行・列

参照形式のリンクは文書内の定義と解決し、通常のリンクノードへ正規化する。定義自体は出力対象のブロックには含めない。

## 既知の制約

- 採用する入力方言はCommonMarkを基礎としたGFMである。他のMarkdown方言固有の構文は解釈しない。
- HTML、画像、脚注はMVP対象外であり、中間表現には定義していない。これらを扱う方針は、必要なマイルストーンで仕様を確定してから追加する。
- CommonMark/GFMが通常テキストとして受理する不完全な記法は、推測でエラーや警告にしない。元の文字をテキストノードとして保持する。
- テーブルセルの複数ブロックやHTMLの `<br>` など、GFMテーブルで直接表現されない構造は保持対象外である。
- ソフト改行と明示改行は構文上区別して保持するが、出力先ごとの表現方法は各Converterのマイルストーンで決定する。
