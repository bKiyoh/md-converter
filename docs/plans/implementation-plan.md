確定した製品仕様は `../specs/product-spec.md` と機能別仕様書、変換仕様は

`../README.md` に従う。

完了済みマイルストーンの詳細と当時の判断経緯は、
`../archive/implementation-plan-completed.md` に保存する。

## 次の変更を開始する手順

新機能または既存仕様を変更する場合は、コードより先に次の順序で更新する。

1. `../README.md` から対象機能の正本を特定する
2. 対象の機能別仕様書を更新する
3. この文書に新しいマイルストーンを追加する
4. 対象範囲、対象外、完了条件、必要なテストを定義する
5. 1つのマイルストーンだけを実装・検証する

仕様を変更しない不具合修正では、既存仕様と再現条件を確認し、必要な回帰テストを
追加する。新しい製品判断が必要になった場合は、不具合修正として推測で処理せず、
先に該当仕様書とこの計画を更新する。

## マイルストーン：正式リリース監査 High / Medium 対応

### 目的

2026-08-01の正式リリース前調査で報告されたHigh 2件、Medium 9件を、既存の責務分離と
ローカル完結の方針を維持して解消する。各指摘は独立して検証し、項目単位のコミットに
分ける。

### 対象範囲

- H-1：MarkdownプレビューのリンクURLをブラウザと同等に正規化して検証する
- H-2：LocalStorage保存失敗を永続表示し、利用者が再試行できるようにする
- M-1：破損したタブ保存値を起動直後に上書きせず、復旧用コピーを提供する
- M-2：画像などの未対応Markdownを代替テキストと警告へ変換する
- M-3：リアルタイム変換をデバウンスし、検索ハイライト数に上限を設ける
- M-4：監査で検出された開発・ビルド依存の脆弱性を安全な版へ更新する
- M-5：タブ名変更と並べ替えをキーボードだけで操作可能にする
- M-6：削除済みタブの完全削除前に確認ダイアログを表示する
- M-7：faviconとタイトル画像を表示用途に合う寸法・容量へ最適化する
- M-8：正式対応ブラウザと確認方法、未確認範囲を文書化する
- M-9：第三者依存のライセンス通知と画像資産の由来記録を追加する

### 対象外

- 調査結果のLow項目
- バックエンド、外部API、クラウド保存、ユーザー登録
- 高機能Markdownエディターや新しい出力形式
- 調査結果と無関係なUI刷新・大規模リファクタリング

### 完了条件

- High / Medium各項目の再現条件を解消し、必要な仕様書と回帰テストを更新している
- 保存失敗や破損データ、未対応Markdownでも編集中の正常な内容を失わない
- キーボード操作、完全削除確認、長文時の上限が自動テストで確認できる
- 対応ブラウザ、手動確認が必要な項目、ライセンスと画像由来が文書化されている
- `npm run lint`、`npm run type-check`、`npm run test`、`npm run build` が成功する
- `npm audit`で既知のHigh脆弱性が残っていない

### 必要なテスト

- 制御文字を含む危険URLと許可URLのプレビュー回帰テスト
- Storage保存失敗の永続警告、再試行、破損値非上書き、復旧コピーのテスト
- 未対応Markdownを含む複合入力のParser・全Converterテスト
- 変換デバウンスと検索ハイライト上限のテスト
- タブのキーボード操作と完全削除確認・キャンセルのテスト
- 依存更新後の全テスト、ビルド、依存監査
